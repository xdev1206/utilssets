# Gemma 4 PyTorch alignment notes

- Compare the local checkpoint-backed implementation with the Transformers Gemma 4 reference at text-layer, vision-feature, audio-feature, and multimodal-logit boundaries.
- Attention numerical parity requires fp32 softmax followed by casting probabilities back to the query/value working dtype before the value matmul.
- Text RoPE parity still requires direct comparison of the generated cosine/sine factors and rotated Q/K; a local experiment that cast the factors before multiplication increased the error and was reverted.
- The reference main and token-PLE embeddings store their square-root scales as buffers cast to the embedding weight dtype; Python scalar multiplication changes the first-layer inputs (for example, `sqrt(1536)` rounding). Direct comparison after applying BF16 tensor scales gives exact equality for both main and token-PLE embedding outputs (`max_abs=0`). Keep these changes in both local entry points; the temporary end-to-end increase from `0.5` to `0.625` indicates a downstream compensating error, not an embedding mismatch. The PLE context projection scale follows the reference's Python-scalar path and is separate.
- Text RMSNorm should follow the reference's FP32 `torch.pow(mean_squared, -0.5)` formulation rather than substituting `torch.rsqrt`; the operation choice is part of the BF16 numerical path.
- In Gemma 4 layer 0, Q/K/V projections and their Q/K/V norms matched the reference exactly, but the first attention divergence was after RoPE (Q max abs `0.0625`, MSE `3.4171e-06`; K max abs `0.001953125`, MSE `4.2645e-08`). The reference constructs frequencies with expanded batched matrix multiplication and casts `cos/sin` to the input dtype before rotation; the local path now follows both operations.
- After the RoPE fix, layer-0 `cos`, `sin`, pre-RoPE Q/K, and post-RoPE Q/K all match the reference exactly (`MSE=0`, `max_abs=0`). The remaining attention-output difference is therefore after RoPE.
- The reference eager attention recomputes exactly from its captured BF16 Q/K/V and its own mask. A direct raw-BF16 comparison shows layer-0 Q/K/V and relative-K inputs match exactly; the remaining attention-output difference is attributable to the blocked mask mapping described below, so softmax and value aggregation comparisons are only meaningful after the masks are identical. The local GQA expansion remains the reference `expand(...).reshape(...)` layout.
- The runtime gap is caused by the attention backend contract: Transformers loads this checkpoint with default `sdpa`, while the local implementation is eager. Local logits match the reference forced to eager exactly (`max_abs=0`); local versus reference default `sdpa` is `max_abs=0.5`, `mean_abs≈0.05424`, and reference `sdpa` versus eager has the same gap. Final numerical acceptance must therefore either force the reference to eager or implement and validate the same SDPA backend; the eager/eager comparison must not be mixed with the default-backend result.
- The checkpoint-backed reference alignment test now passes `attn_implementation="eager"` during `Gemma4ForConditionalGeneration.from_pretrained` and asserts the loaded text model uses eager. This makes the formal text comparison an explicit eager/eager contract instead of relying on a post-load config mutation or the Transformers default.
- With the explicit eager backend, the checkpoint text-logit test passes exactly. The generation test additionally exposed a separate stopping-contract gap: the reference checkpoint declares EOS IDs `1` and `106`, while the local generator previously ignored EOS and always emitted `max_new_tokens`; generation must stop when every batch item reaches either EOS ID.
- Audio alignment's first confirmed structural mismatch is `audio_tower.output_proj`: the checkpoint and Transformers reference include a nonzero bias (`max_abs=14.875` in the checkpoint), but the local layer was declared with `bias=False`. The loader already requested `output_proj.bias`, so the local declaration must use `bias=True` before deeper audio-layer diagnosis.
- Audio layer 0 attention has a separate confirmed mask-boundary bug: the local mask allowed the key at `q - (attention_context_left - 1)`, while the reference sliding-window predicate requires `distance < attention_context_left - 1` and excludes that farthest key. The lower-bound comparison must therefore be strict.
- After the strict left-boundary fix, the audio end-to-end maximum error decreased from `37.46875` to `30.15625`; after matching the q/k scale constants it is `30.09375`. The remaining attention comparison must continue from the residual layer-0 attention difference.
- Do not relax numerical thresholds until a layer-wise comparison proves the remaining difference is expected dtype rounding rather than a missing mask, projection, or residual operation.
- Audio alignment must build the blocked 5D mask at the model boundary and pass it into every attention layer; the remaining first-layer divergence requires comparing relative-position attention intermediates.
- Audio positional encoding now computes `inv_timescales` in FP32 and then casts it to the active model default dtype. This matches the reference construction-before-casting order and is important because the buffer is non-persistent and is not converted by the local checkpoint loader; the runtime regression test now passes exactly (`MSE=0`, `max_abs=0`).
- With real audio features, layer-0 subsample, position encoding, FFN1, pre-attention norm, and Q/K/V plus relative-K projections match exactly. The local audio path now propagates the subsample mask through both convolution layers, builds the reference-style 4D sliding mask, converts it to BF16 additive values, applies the same blocked padding/gather conversion, and uses `attention_mask.logical_not()` in eager attention. Direct runtime comparison proves the reference and local blocked masks are bitwise identical (`shape=[1,1,3,12,24]`, BF16, `MSE=0`, `max_abs=0`, `0/864` mismatches); the 4D masks also have identical `391` invalid and `234` zero entries. The audio end-to-end max error is `1.1875`. With real features, layers 0 and 1 are exact; layer 2 first diverges in `self_attn` (`max_abs=0.0078125`, 30 elements), while its following RMSNorm amplifies the small perturbation on near-zero vectors (`max_abs=270.65625`). The next diagnostic must compare layer-2 attention score/softmax/post-projection stages.
- Layer 2 attention tracing found the first divergence in softcap: hidden states, position embeddings, mask, Q/K/V, relative-K projection, AC, BD, and pre-softcap scores were bitwise identical. The fused local `tanh(scores / cap) * cap` differed from the reference's three-step division/tanh/multiplication sequence by at most `7.6293945e-06`. The local path now matches the reference's softcap steps, `F.softmax`, conditional mask application, and contiguous output before post projection.
- The softcap discrepancy was caused by dtype: the reference stores softcap as a non-persistent buffer, which becomes BF16 under the BF16 model, while the local path used a Python float. The local softcap is now a non-persistent tensor buffer created under the model construction dtype; rerun the runtime audio gate to verify the downstream error.
- Vision tracing found patch embedding, layer-0 input norm, Q/K/V projections, and Q/K norms bitwise identical. The first vision divergence is inside self-attention, consistent with the local 2-D RoPE multiplying with FP32 cosine/sine values before the final cast, while the reference casts cosine/sine to BF16 before rotation. The local vision RoPE now casts both factors to the state dtype before the rotation multiply/add.
- After the RoPE fix, all 16 valid vision-layer boundaries are bitwise identical. The remaining tower difference was in pooling: the reference casts the FP32 average-pool result to BF16 before multiplying by `sqrt(hidden_size)`, while local code scaled first and cast afterward. The local pooler now matches the reference cast order.
- The remaining vision scaling detail is also explicit: the reference converts the BF16 pooled result to FP32 before multiplying by `sqrt(hidden_size)`. The local final scaling now uses the same explicit FP32 conversion.
- The residual sparse tower mismatch came from trimming padding before pooling. The reference keeps padded patches in the pooling matmul after zeroing their hidden states, then removes padding pool bins with a mask. The local vision model now retains padding through encoder/pooling and applies the same pool mask, preserving the reference reduction order.
- Runtime validation now passes both the standalone vision-feature comparison and the image-text logits comparison after the RoPE and pooling fixes.
- Runtime-created tensors and non-persistent buffers must be checked against the reference construction dtype; mathematically equivalent formulas can diverge under BF16 default-dtype construction.
